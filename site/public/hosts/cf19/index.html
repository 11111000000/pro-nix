cf19

cf19

cf19 — Panasonic Let’s Note CF-MX ноутбук, одна из более старых машин в кластере. Класс железа — «BIOS-эра ноутбук с странным keyboard-контроллером»; почти каждая строка kernel-параметров в host-конфиге — обход этого.

  • Класс. Ноутбук, BIOS-загрузка, не EFI.
  • Загрузка. GRUB на /dev/sda, без EFI NVRAM-записей.
  • Ядро. linuxPackages_6_6 (LTS-линейка, стабильнее на этом поколении).
  • Роли. laptop, tor.

Список kernel-параметров

boot.kernelParams = [
  "i8042.reset"
  "i8042.nomux"
  "mitigations=off"
  "preempt=full"
  "mem_sleep_default=s2idle"
];
  • i8042.reset + i8042.nomux — i8042-keyboard-контроллер на этом ноутбуке иногда не перечисляет тачпад после resume. Сброс контроллера на resume + отключение multiplex-режима обходит баг.
  • mitigations=off — отключить CPU-уязвимости-mitigations. Это машина одного пользователя без untrusted-кода; perf-cost от mitigations не стоит маргинальной security-выгоды. Не подходит для multi-user или shared-машины.
  • preempt=full — полная преемпция. Улучшает интерактивную latency для Emacs (который всегда «работает») ценой небольшого throughput-хита на долгих CPU-задачах.
  • mem_sleep_default=s2idle — современный suspend-режим. Ноутбук не поддерживает deep (S3) надёжно; s2idle работает на всех свежих ядрах.

modprobe-конфиг

Базовый modules/host-policies.nix (под mkIf isCf19) добавляет:

options iwlwifi power_save=0
options iwlmvm power_scheme=1
options cfg80211 ieee80211_default_rc_algo=minstrel_ht
options iwlwifi 11n_disable=8
options iwlmvm uapsd_disable=1
  • iwlwifi power_save=0 — отключить power-save на WiFi-чипе. Resume из s2idle может оставить чип в low-power-состоянии, что мешает re-association.
  • iwlmvm power_scheme=1 — то же, для драйвера mvm (Multi-Virtual-MAC).
  • cfg80211 ieee80211_default_rc_algo=minstrel_ht — использовать minstrel_ht как rate-control-алгоритм. Default (PID) нестабилен на этом чипе.
  • iwlwifi 11n_disable=8 — отключить 802.11n-фичи, вызывающие просадки throughput в этой версии драйвера.
  • iwlmvm uapsd_disable=1 — отключить U-APSD (unscheduled automatic power-save delivery), несовместимый с power_save=0.

Post-resume WiFi-recovery

Даже с modprobe-конфигом WiFi-чип иногда отказывается re-associate после s2idle. scripts/ops-wifi-recover.sh подключён к resume- и power-up-командам:

powerManagement.resumeCommands = lib.mkAfter ''
  for n in XHCI RP05; do
    if ${pkgs.gawk}/bin/gawk -v d="$n" '$1==d && $3 ~ /\*enabled/' /proc/acpi/wakeup >/dev/null 2>&1; then
      echo "$n" > /proc/acpi/wakeup || true
    fi
  done
  ${wifiRecover}/bin/ops-wifi-recover || true
'';

ops-wifi-recover.sh имеет три эскалационные стратегии:

  1. nmcli radio wifi off, затем nmcli radio wifi on.
  2. nmcli connection reload + nmcli connection up <active-profile>.
  3. systemctl try-restart NetworkManager.

Каждая стратегия сначала пингует gateway; при успехе — return 0; при провале — пробует следующую.

dbus-regression override

tests/vm/cf19-switch-dbus-regression.nix был добавлен после того, как nixos-rebuild switch многократно вызывал падение хоста в TTY во время dbus-broker restart’а, происходящего как часть systemd-активации. Фикс — отключить dbus-релоад полностью:

systemd.services.dbus = {
  reloadIfChanged  = lib.mkForce false;
  restartIfChanged = lib.mkForce false;
  restartTriggers  = lib.mkForce [ ];
  stopIfChanged    = lib.mkForce false;
};

systemd.user.services.dbus = {
  reloadIfChanged  = lib.mkForce false;
  restartIfChanged = lib.mkForce false;
  restartTriggers  = lib.mkForce [ ];
  stopIfChanged    = lib.mkForce false;
};

Trade-off: dbus-демон не релоадится после switch. Новая dbus-конфигурация вступает в силу только при полной перезагрузке. Пользователь должен перезагружать cf19 после значительных dbus-изменений (на практике редко).

Storage layout

fileSystems."/" = lib.mkForce {
  device = "/dev/disk/by-uuid/<root-uuid>";
  fsType = "ext4";
};

fileSystems."/boot" = lib.mkForce {
  device = "/dev/disk/by-uuid/<boot-uuid>";
  fsType = "ext4";
};

fileSystems."/mnt/sda4" = lib.mkForce {
  device = "/dev/disk/by-uuid/<sda4-uuid>";
  fsType = "ext4";
  options = [ "noatime" ];
};

swapDevices = [ { device = "/dev/disk/by-uuid/<swap-uuid>"; } ];

/boot на маленьком ext4-разделе (на этой машине нет EFI). / — главный системный раздел. /mnt/sda4 — data-раздел, монитируется в четвёртый partition на первом диске (без label, просто номер partition’а — выбор пользователя). Swap на собственном partition’е.

boot.initrd.kernelModules — правильный набор для этого железа:

boot.initrd.kernelModules = [ "ahci" "ata_piix" "usb_storage" "sd_mod" ];

ata_piix — IDE-совместимый драйвер для storage-контроллера ноутбука. ahci — для (редко используемого) SATA-порта.

Сессия

cf19 импортирует profile-exwm-minimal.nix, так что EXWM — primary сессия. Sway и i3 тоже установлены (импортируются session-sway.nix и session-i3.nix); пользователь выбирает в GDM-сессион-чузере.

Cinnamon и fbterm-tty2 принудительно выключены:

services.xserver.desktopManager.cinnamon.enable = lib.mkForce false;
systemd.services."fbterm-tty2".enable              = lib.mkForce false;

Исключение Cinnamon — потому что EXWM-minimal профиль уже устанавливает cinnamon.enable = false (default); mkForce делает это липким, даже если поздний модуль попытается включить. fbterm-tty2 исключён, потому что занимает /dev/tty2 и может конфликтовать с display-manager grab.

Tor hidden service

cf19 опционально подключает SSH hidden service:

# базовый конфиг (configuration.nix)
pro-peer.enable = true;
pro-peer.enableKeySync = true;

# host override
pro-peer.allowTorHiddenService = true;  # в modules/host-policies.nix (mkIf isCf19)

Onion-hostname регистрируется в pro.hosts.cf19.onion (пустая строка до первой активации). После nixos-rebuild switch onion host лежит в /var/lib/tor/ssh_hidden_service/hostname.

NFS

cf19 монитирует desktop’овский /srv/nfs в /mnt/desktop:

pro.nfs.client.enable = true;

modules/pro-nfs.nix настраивает autofs-unit mnt-desktop.automount с timeo=10,retrans=1,x-systemd.mount-timeout=3,nofail. 3-секундный таймаут хардкоден — ls /mnt/desktop возвращает No such file or directory (не хэнг), когда desktop выключен.

Composition

hosts/cf19/composition.nix — минимальный:

{ lib, pkgs, ... }:
let
  tor = import ../../modules/system-package-sets-tor.nix { inherit pkgs; };
in
{
  pro.profiles.exwmMinimal.enable = lib.mkDefault true;
  environment.systemPackages = tor.torControlPackages;
}

Только exwmMinimal (EXWM-сессия) и tor.torControlPackages (pro-tor CLI, torwrap, torsocks, proxychains). Без Haskell, без desktopHeavy, без dev-toolchain.

Post-switch чек-лист

# 1. SSH-ключи (один раз)
ssh-copy-id -i ~/.ssh/id_ed25519.pub <user>@cf19.local

# 2. BIOS-mode sanity
cat /proc/cmdline | tr ' ' '\n' | rg i8042
# Должно включать: i8042.reset, i8042.nomux
# Также: mitigations=off, preempt=full, mem_sleep_default=s2idle

# 3. WiFi-recovery скрипт установлен
command -v ops-wifi-recover
sudo ops-wifi-recover    # если WiFi не возвращается после s2idle

# 4. Avahi
getent hosts desktop.local
getent hosts cf19.local

# 5. NFS autofs
systemctl status mnt-desktop.automount
ls /mnt/desktop                # ≤ 3 с, даже если desktop выключен

# 6. EXWM-сессия
ls /run/systemd/system/display-manager.service
# Должен быть (gdm). Login → EXWM.
# Если чёрный экран: Ctrl+Alt+F2, логин в tty2, посмотрите
# ~/.local/share/xorg/Xorg.0.log

# 7. Emacs soft-reload
# Внутри Emacs: M-x pro/reload-config
# Должен перезагрузить 64 модуля без ошибок.
