# cf19

`cf19` is a **Panasonic Let's Note CF-MX** laptop, one of the older
machines in the cluster. The hardware class is "BIOS-era laptop
with weird keyboard controller" — almost every kernel-parameter line
in the host config is a workaround for that.

* **Class.** Laptop, BIOS boot, not EFI.
* **Boot.** GRUB on `/dev/sda`, no EFI NVRAM writes.
* **Kernel.** `linuxPackages_6_6` (the LTS line, more stable on this
  generation).
* **Roles.** `laptop, tor`.

## The kernel parameter list

```
boot.kernelParams = [
  "i8042.reset"
  "i8042.nomux"
  "mitigations=off"
  "preempt=full"
  "mem_sleep_default=s2idle"
];
```

* `i8042.reset` + `i8042.nomux` — the i8042 keyboard controller on this
  laptop occasionally fails to enumerate the touchpad after resume.
  Resetting it on resume + disabling multiplex mode works around the
  bug.
* `mitigations=off` — disable CPU vulnerability mitigations. This is
  a single-user machine with no untrusted code; the perf cost of
  mitigations is not worth the marginal security benefit. **Not**
  appropriate for a multi-user or shared machine.
* `preempt=full` — full preemption. Improves interactive latency
  for Emacs (which is always "running") at the cost of a small
  throughput hit on long-running CPU jobs.
* `mem_sleep_default=s2idle` — modern suspend mode. The laptop does
  not support `deep` (S3) reliably; `s2idle` works on all recent
  kernels.

## The modprobe config

The base `modules/host-policies.nix` (under `mkIf isCf19`) adds:

```
options iwlwifi power_save=0
options iwlmvm power_scheme=1
options cfg80211 ieee80211_default_rc_algo=minstrel_ht
options iwlwifi 11n_disable=8
options iwlmvm uapsd_disable=1
```

* `iwlwifi power_save=0` — disable power-save on the WiFi chip.
  Resume from s2idle can leave the chip in a low-power state that
  prevents re-association.
* `iwlmvm power_scheme=1` — same, for the mvm (Multi-Virtual-MAC)
  driver.
* `cfg80211 ieee80211_default_rc_algo=minstrel_ht` — use minstrel_ht
  as the rate-control algorithm. The default (PID) is unstable on
  this chip.
* `iwlwifi 11n_disable=8` — disable 802.11n features that cause
  throughput drops in this driver version.
* `iwlmvm uapsd_disable=1` — disable U-APSD (unscheduled automatic
  power-save delivery), which is incompatible with `power_save=0`.

## The post-resume WiFi recovery

Even with the modprobe config, the WiFi chip sometimes refuses to
re-associate after s2idle. `scripts/ops-wifi-recover.sh` is wired
into the resume and power-up commands:

```bash
powerManagement.resumeCommands = lib.mkAfter ''
  for n in XHCI RP05; do
    if ${pkgs.gawk}/bin/gawk -v d="$n" '$1==d && $3 ~ /\*enabled/' /proc/acpi/wakeup >/dev/null 2>&1; then
      echo "$n" > /proc/acpi/wakeup || true
    fi
  done
  ${wifiRecover}/bin/ops-wifi-recover || true
'';
```

`ops-wifi-recover.sh` has three escalating strategies:

1. `nmcli radio wifi off` then `nmcli radio wifi on`.
2. `nmcli connection reload` + `nmcli connection up <active-profile>`.
3. `systemctl try-restart NetworkManager`.

Each strategy pings the gateway first; on success, it returns 0; on
failure, it tries the next.

## The dbus-regression override

The `cf19-switch-dbus-regression.nix` test was added after a
`nixos-rebuild switch` repeatedly caused the host to fall to TTY
during the dbus-broker restart that happens as part of systemd
activation. The fix is to disable dbus reloading entirely:

```nix
systemd.services.dbus = {
  reloadIfChanged  = lib.mkForce false;
  restartIfChanged = lib.mkForce false;
  restartTriggers  = lib.mkForce [ ];
  stopIfChanged    = lib.mkForce false;
};

systemd.user.services.dbus = {
  reloadIfChanged  = lib.mkForce false;
  restartIfChanged = lib.mkForce false;
  restartTriggers  = lib.mkForce [ ];
  stopIfChanged    = lib.mkForce false;
};
```

The trade-off: the dbus daemon is not reloaded after a switch. New
dbus configuration takes effect only on a full reboot. The user
is expected to reboot `cf19` after major dbus changes (rare in
practice).

## The storage layout

```
fileSystems."/" = lib.mkForce {
  device = "/dev/disk/by-uuid/d7d6e5f8-2c00-47ad-931a-a6b73a1cdcc2";
  fsType = "ext4";
};

fileSystems."/boot" = lib.mkForce {
  device = "/dev/disk/by-uuid/c3ff38e8-0de3-427a-983f-86871ed38d32";
  fsType = "ext4";
};

fileSystems."/mnt/sda4" = lib.mkForce {
  device = "/dev/disk/by-uuid/f422300d-3217-4bb8-b611-e88491c6901d";
  fsType = "ext4";
  options = [ "noatime" ];
};

swapDevices = [ { device = "/dev/disk/by-uuid/68ade83c-1e5b-4f37-a13f-2c386be87be6"; } ];
```

`/boot` is on a small ext4 partition (no EFI on this machine). `/`
is the main system partition. `/mnt/sda4` is a data partition
mounted at the fourth partition on the first disk (no label, just
the partition number — the user's choice). Swap is on its own
partition.

The `boot.initrd.kernelModules` are the right set for this hardware:

```nix
boot.initrd.kernelModules = [ "ahci" "ata_piix" "usb_storage" "sd_mod" ];
```

`ata_piix` is the IDE-compatible driver for the laptop's storage
controller. `ahci` is for the (rarely used) SATA port.

## The session

`cf19` imports `profile-exwm-minimal.nix`, so EXWM is the primary
session. Sway and i3 are also installed (`session-sway.nix` and
`session-i3.nix` are imported); the user picks at the GDM session
chooser.

Cinnamon and fbterm-tty2 are **forcibly off**:

```nix
services.xserver.desktopManager.cinnamon.enable = lib.mkForce false;
systemd.services."fbterm-tty2".enable              = lib.mkForce false;
```

The Cinnamon exclusion is because the EXWM-minimal profile already
sets `cinnamon.enable = false` (default); `mkForce` makes it stick
even if a later module tries to enable it. fbterm-tty2 is excluded
because it occupies `/dev/tty2` and can conflict with the
display-manager grab.

## The Tor hidden service

`cf19` opts into the SSH hidden service:

```nix
# base config (configuration.nix)
pro-peer.enable = true;
pro-peer.enableKeySync = true;

# host override
pro-peer.allowTorHiddenService = true;  # in modules/host-policies.nix (mkIf isCf19)
```

The onion hostname is registered in `pro.hosts.cf19.onion` (an empty
string until the first activation generates one). After
`nixos-rebuild switch`, the onion hostname is at
`/var/lib/tor/ssh_hidden_service/hostname`.

## NFS

`cf19` mounts the desktop's `/srv/nfs` at `/mnt/desktop`:

```nix
pro.nfs.client.enable = true;
```

`modules/pro-nfs.nix` configures the autofs unit
`mnt-desktop.automount` with `timeo=10,retrans=1,x-systemd.mount-timeout=3,nofail`.
The 3-second timeout is hard-coded — `ls /mnt/desktop` returns
`No such file or directory` (not a hang) when the desktop is
offline.

## The composition

`hosts/cf19/composition.nix` is the **minimal** one:

```nix
{ lib, pkgs, ... }:
let
  tor = import ../../modules/system-package-sets-tor.nix { inherit pkgs; };
in
{
  pro.profiles.exwmMinimal.enable = lib.mkDefault true;
  environment.systemPackages = tor.torControlPackages;
}
```

Only `exwmMinimal` (the EXWM session) and `tor.torControlPackages`
(`pro-tor` CLI, `torwrap`, `torsocks`, `proxychains`). No Haskell,
no `desktopHeavy`, no `dev` toolchain.

## Post-switch checklist

```bash
# 1. SSH keys (one-time)
ssh-copy-id -i ~/.ssh/id_ed25519.pub az@cf19.local

# 2. BIOS-mode sanity
cat /proc/cmdline | tr ' ' '\n' | rg i8042
# Should include: i8042.reset, i8042.nomux

# 3. WiFi recovery script is installed
command -v ops-wifi-recover
# Use it after s2idle if WiFi doesn't come back
sudo ops-wifi-recover

# 4. Avahi
getent hosts desktop.local    # should return desktop's LAN IP
getent hosts cf19.local       # should return cf19's LAN IP

# 5. NFS autofs
systemctl status mnt-desktop.automount
ls /mnt/desktop                # ≤ 3 s even if desktop is offline

# 6. EXWM session
ls /run/systemd/system/display-manager.service
# Should be present (gdm). Login → EXWM.
# If black screen: Ctrl+Alt+F2, log in to tty2, check
# ~/.local/share/xorg/Xorg.0.log

# 7. Emacs soft-reload
M-x pro/reload-config
# Should reload all 60 modules without errors
```
