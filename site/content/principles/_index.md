В репозитории нет design-документа, нет диаграммы архитектуры и нет
RFC-процесса. Есть **пять принципов**, которые ожидаются от каждого,
кто трогает код. Они короткие, легко запоминаются и почти всегда
применимы.

## 1. Декларативно везде

Если состояние можно выразить значением — это значение. Системные
сервисы, переменные Emacs, дефолты fontconfig, MCP-серверы агентов —
всё записывается как данные и читается во время активации. Единственные
side-effects в репо — activation-скрипты и обёртки `writeShellScriptBin`;
всё остальное — `mkOption` или `defcustom`.

> **Проверь сам.** Возьми любой модуль в `modules/`. Без запуска кода
> должно быть понятно, какие пакеты он ставит, какие сервисы стартует
> и какие файлы пишет.

## 2. Идемпотентность + soft-reload

Каждая операция должна быть безопасной для повтора. `just switch` не
важно, запускали ли его раньше; `pro/reload-config` (C-x M-c) не
важно, сколько раз уже перезагружали; `home.activation.pro-agent-configs-deploy`
не перезапишет ваши локальные правки.

Самое важное следствие — **soft-reload контракт**. Модули, у которых
есть persistent state (child-frames, фоновые процессы, кэшированные
значения), регистрируют teardown-функции на `pro--after-reload-hook`.
После soft-reload эти модули пересоздают свой state из свежезагруженного
кода — см. `emacs/base/modules/pro-reload.el:11-22` для контракта.

## 3. Единственный источник правды

У трёх фактов ровно по одному каноническому месту:

| Факт | Источник правды |
|------|-----------------|
| Список хостов и роли | `modules/pro-hosts.nix#pro.hosts` |
| Глобальные клавиши | `emacs-keys.org` (org-таблица, парсится в runtime) |
| Per-host секреты и override'ы | `local.nix` (gitignored) |

Всё остальное — **выводимо**. Сгенерированный `ssh_config.d/pro.conf`
выводится из `pro.hosts`. Порт `emcp` выводится из `pro-emcp.el`.
Chromium-slice с `MemoryMax` выводится из
`system-package-sets-desktop-heavy.nix`. Никакого дублирования.
Если вы видите один и тот же факт в двух местах — это баг.

## 4. С явной позицией + прозрачно

Когда проект делает выбор, выбор виден:

* `pro-ui-default-theme = 'tao-yang` (светлая, yang)
* `pro-ai-backend = 'aitunnel` (с openrouter + siliconflow как альтернативы)
* `pro-tor local` (единственный режим, переживающий гостиничный Wi-Fi)
* `services.headscale.enable = true` на `desktop`, `lib.mkForce false`
  на остальных
* `pro-ui-font-family = "Aporetic Sans Mono"` (с fallback на DejaVu)

Позиция поддерживается через `lib.mkDefault` (так что хосты могут
переопределить per-machine) или тем, что выбор лежит внутри одного
`composition.nix` (выход на уровне хоста — одна строка в
`hosts/<host>/composition.nix`). Прозрачность обеспечивается комментариями
в шапках модулей (см. любой `modules/pro-*.nix` для шаблона
"Назначение / Цель / Контракт / Proof").

## 5. Слоистая композиция

Три слоя, каждый полезен сам по себе:

* **Системный слой.** Чистый NixOS. Можно пользоваться репо, ни разу
  не открыв Emacs.
* **Слой Emacs.** Чистый Emacs. Nix-систему можно заменить, и
  `pro-*.el` всё равно загрузится.
* **Слой агентов.** Чистые конфиги агентов. `local-templates/{pi,opencode}/`
  — полный набор dotfiles, с которым агент может работать на
  non-NixOS хосте.

Внутри каждого слоя — ещё слои. Emacs-бутстрап имеет четыре фазы
(`early-init.el` → `init.el` → `site-init.el` → `pro-emacs-base-start`).
NixOS-flake имеет `mkHost` (полный конфиг) и `mkVmHost` (минимальный
baseline без `configuration.nix`). Сеть имеет три независимых слоя
(LAN-mDNS, mesh, SSH-нейминг), которые композируются, не завися друг
от друга.

## Пять принципов одним предложением

> **Факт живёт ровно в одном месте; значение всегда выводимо;
> вывод всегда идемпотентен; выбор всегда виден; слои всегда
> композируются.**
